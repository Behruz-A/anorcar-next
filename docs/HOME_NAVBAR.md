# Shared public navigation

The existing Nestar `Top` component and SCSS remain shared by the public layouts. The current design uses Deep Navy `rgba(11, 31, 51, 0.78)`, 12px backdrop blur, white labels/icons, `#F04428` active/hover accents and a translucent white bottom border. The existing white-lettering ANORCAR logo variant is reused; no asset or branding was replaced. Wide gutters, shortcuts and account separator/caret remain. Existing routes, authentication, profile/admin menu, favorites, search and language switching remain intact. No notification counts are fabricated. The separate admin console keeps its management layout.

The shared public `#top` is sticky and reserves its height on internal pages. The homepage alone uses a zero-height sticky wrapper so its unchanged hero image extends behind the navbar. Hero top padding includes the navbar height plus clearance. Public wrappers grow naturally so the sticky header stays within the full page. Existing hero/detail offsets for the former fixed navbar are removed. Desktop height is 80px; the existing two-row responsive navigation uses 120px below 1350px and 112px below 600px. Grid rows and 44px touch targets fit those heights; links scroll inside their row instead of overflowing the page.

A passive, cleaned-up scroll listener toggles only background/shadow after 8px: the scrolled navy opacity is .96. No height/position transition occurs during scroll. Initial state is deterministic for SSR/hydration, and reduced-motion preferences disable the visual transition. Search and account/language menus retain their MUI portals above the header's z-index. These rules supersede the previous white navbar design.

Validation: TypeScript, zero-warning lint, migration/search behavior checks and shared/desktop/mobile Sass compilation passed. Navbar fixtures exercise guest and USER/AGENT/ADMIN controls, active public routes in desktop/mobile branches, scroll state/listener cleanup and EN/KR/RU switching. No browser surface was available for screenshots or actual layout-shift measurements; responsive sizing and hero clearance were inspected in the compiled styles.

HTTP smoke checks passed on `/`, `/car`, `/car/compare`, `/agent`, `/community`, `/mypage`, `/cs` and `/account/join`, with the shared navbar and existing white-lettering logo present. Account and language menu open/close handlers also pass the isolated interaction checks. No backend API, GraphQL operation or business logic was changed for this navbar redesign.

## Navbar search panel

The existing search shortcut now opens an anchored MUI Popover with an autofocus input, clear action, six existing brand records with local logo resolution and up to four distinct model suggestions from real active cars. Existing `getBrands`/`getCars` queries run only while open. Suggestions use the existing views-desc sort over the first twelve listings; they are listing-based suggestions, not an aggregate of every model in the database. Real year/price/location are displayed rather than invented inventory counts. An exact brand name filters by brand ID, other input uses the existing escaped model/title search, and Enter/View All/model links reuse the existing Cars filter URL. A 250ms debounce, loading/error/retry/empty states, Escape/click-away closing, focus restoration and narrow-screen sizing are retained through the existing MUI conventions. No new component architecture, dependency, backend operation or data changes. EN/KR/RU labels are included. `scripts/check-navbar-search.cjs` covers lazy queries, open/close, real brands, model deduplication, brand selection, route payloads, escaping and errors.
